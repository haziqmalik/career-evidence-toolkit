# Executive Technical Resume

Clone `assets/reference.docx`; never overwrite it.

## Purpose

Executive mode should answer why the candidate is unusually valuable for the target role. Emphasize progression, judgment, business-to-technical translation, leadership, delivery ownership, and selected proof. Do not pour an ATS resume into a decorative layout.

## Workflow

1. Read `artifact-template.json` and resolve its paths relative to this skill.
2. Use an available document capability to clone and populate the reference.
3. Build a structured content model before filling layout cells.
4. Populate supported placeholders, preserve mixed-run formatting, and remove unused optional containers completely.
5. Render, inspect, rebalance by complete semantic blocks when needed, and re-render.

## Evidence and pagination

- Maximum two pages; never force a second page.
- Prefer fewer, stronger evidence blocks proving distinct dimensions.
- Preserve historical titles, claim strength, project maturity, and verified metrics.
- Page one establishes positioning, progression, operating model, and concise proof.
- Page two, when justified, provides project, impact, leadership, production, and education evidence.
- Do not repeat the full page-one hero or sidebar on page two.

## Visual contract

- Coral is a micro-accent; meaningful body and evidence text remains dark.
- Preserve bullet glyph and body-text run roles.
- Preserve the dynamic PAGE field in the footer.
- Do not solve overflow primarily by shrinking text, reducing contrast, crushing spacing, or narrowing evidence columns.
- Remove unresolved placeholders, empty containers, orphan headings, stranded bullets, clipping, overlap, and weak spill pages.

User instructions control content. The retained reference controls unrequested appearance.
