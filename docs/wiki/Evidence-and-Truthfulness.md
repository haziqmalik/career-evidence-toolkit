# Evidence and Truthfulness

Career Evidence Toolkit is built to improve presentation **without changing the truth of the underlying career record**.

## Core rule

A job description can change what is emphasized. It must not change what actually happened.

The toolkit should therefore distinguish between:

- **Verified evidence** — supported by documents, profiles, project records, credential pages, or another reliable source.
- **User-provided evidence** — facts explicitly supplied or corrected by the user.
- **Derived framing** — concise wording that faithfully summarizes supported facts.
- **Unsupported claims** — achievements, metrics, technologies, responsibilities, or credentials that are not evidenced.

Unsupported claims should not be added merely because they improve keyword overlap.

## Claim-strength preservation

When rewriting, the strength of a statement should remain faithful to the evidence.

Examples:

| Evidence supports | Safe framing | Avoid |
| --- | --- | --- |
| Contributed to a platform | “Contributed to…” | “Led the entire platform…” |
| Worked with AWS services | “Deployed workloads using…” | “AWS expert” unless separately supported |
| Project used microservices | “Worked within a microservices architecture” | “Designed the microservices architecture” without evidence |
| Historical metric is verified | State it with scope/time context | Recasting it as a current metric |

## Role targeting

Targeting should work by selecting and ordering relevant evidence:

1. identify what the role requires;
2. find supported experience matching those requirements;
3. prioritize the strongest matches;
4. omit low-value detail when space is limited;
5. preserve important caveats, dates, scope, and ownership boundaries.

## Metrics

Use production metrics only when they are supported and properly scoped. Historical figures should be identified as historical rather than silently presented as current.

## Technology keywords

A technology may be included when the evidence shows meaningful use. Do not add technologies solely because a vacancy lists them.

## When evidence is missing

The correct output is a gap, not an invention. The toolkit may point out that a requirement is not evidenced and allow the user to provide additional proof if it exists.

## Why this matters

A resume has to survive interviews, reference checks, technical discussion, and long-term professional scrutiny. Evidence-first generation makes the document easier to defend because each meaningful claim is anchored in the user's real record.
