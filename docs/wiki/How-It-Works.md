# How It Works

Career Evidence Toolkit separates **career evidence**, **resume selection**, and **presentation** so that a polished resume does not require inventing or silently strengthening claims.

## The evidence-first pipeline

```text
Evidence sources
      ↓
Private career workspace
      ↓
Master resume + certificate registry
      ↓
Role / vacancy analysis
      ↓
Relevant evidence selection
      ↓
ATS or Executive presentation
      ↓
Validated application resume
```

## 1. Evidence collection

Evidence may come from existing CVs, professional profiles, project records, certificate files, public credential pages, and user-provided corrections. The toolkit should distinguish between verified facts, user-supplied facts, and information that is not yet supported.

## 2. Master resume maintenance

The master resume is intentionally comprehensive. It acts as the durable source of truth for later resume generation rather than trying to fit every career detail into one application document.

The maintainer skill can initialize the document, merge new evidence, correct stale information, and preserve relevant historical context.

## 3. Credential reconciliation

Professional certificates are tracked separately so duplicate, missing, stale, or conflicting records can be identified before they are copied into a resume.

## 4. Target analysis

For a job title or vacancy, the toolkit identifies the responsibilities, technical themes, seniority signals, and evidence requirements that matter for that target.

It then selects the strongest relevant evidence available in the private career workspace. Relevance changes; the underlying facts do not.

## 5. Resume generation

Two presentation modes are bundled:

- **ATS Professional Resume** — conventional, concise, single-column, parsing-friendly output.
- **Executive / Senior Technical Resume** — more selective, editorial, and human-facing for senior technical and leadership applications.

Both should be generated from the same verified career evidence.

## 6. Validation

Before a document is treated as finished, the workflow should check for unsupported claims, accidental personal-data leakage, layout problems, template corruption, and obvious inconsistencies.

## Why this architecture matters

A resume generator that writes directly from a job description is prone to exaggeration. Career Evidence Toolkit instead treats the job description as a **selection problem**: it determines which verified facts deserve emphasis, not which new facts should be invented.
